BPP Team Guide

Git, the Simple Version

How the three of us work on our shared files without stepping on each other.

The whole idea, in one breath

Git does two things for us. That is all you need to hold in your head. Every word in this guide is just a name for one of the moving parts underneath these two ideas.

⏱A time machine

Every version you save is kept forever, labeled with who and why. Any mistake can be undone. Nothing is ever truly lost.

👥Safe multiplayer

All three of us can work on the same files at the same time. Git combines the work. Nobody overwrites anybody.

01Five words you need to know
Word 1

Commit

"Save, but permanent, and with a sticky note explaining what changed."
A commit is one snapshot of the project, plus a short note. Each one is stamped with your name, the date, and your message. They link in a chain, and that chain is our history. Think of each commit as a numbered save in a video game: you can always reload one.

Word 2

Branch

"Your own safe lane to work in, so the official version stays clean."
There is one official version of our files, called main. You never edit main directly. Instead you make a branch, which is your own parallel copy. You do your work there, and main stays untouched and safe to use the whole time. When your work is ready, it gets added back into main. This is what lets all three of us work at once: each person on their own branch.
Main stays clean. You branch off it and work safely.

Word 3

Push & Pull

"Pull brings everyone's work down to you. Push sends yours up to everyone."
Our shared files live on GitHub, the website that holds the official copy. Your computer has its own full copy. Pull = download the latest from GitHub before you start. Push = upload your work so the others can see it. Pull when you sit down, push when you finish.

Word 4

Pull Request

"Here is my work. Please look it over, then add it to the official version."
A Pull Request (or PR) is how your branch becomes part of main. It is a review checkpoint. GitHub shows exactly what you changed, a teammate can comment or ask questions, and then someone clicks Merge to fold your work in. Nothing reaches main except through a PR. This is how we all see who changed what, and why.

Word 5

Issue

"A tracked note. A bug, an idea, or a to-do for our files."
An Issue is a lightweight note attached to the project. Something like "the discovery prep skill is missing a step" or "we should add X to our notes." It has a title, a description, and a place to discuss. An issue often turns into a branch, then a PR. Quick reminder: Monday still runs our actual project work. Issues are only for the shared files themselves.
02The everyday loop, six steps

Once you are set up, this is the entire job. The same six steps every time. With GitHub Desktop (the friendly app), each step is just a button, so you never touch a command line.

1

Pull

Open GitHub Desktop and get everyone's latest work before you start.

Button: Fetch / Pull
2

New branch

Make a branch for the task you are about to do. Give it a short name.

Button: New Branch
3

Do the work

Edit the files normally. GitHub Desktop watches and lists every change.

No button, just work
4

Commit

Write a one-line summary of what you changed, then save the snapshot.

Button: Commit
5

Push

Send your branch up to GitHub so the rest of us can see it.

Button: Push origin
6

Pull Request

Open a PR. A teammate reviews it, then it gets merged into main.

Button: Create Pull Request
That is the whole rhythm: pull, branch, work, commit, push, PR. Everything earlier in this guide just explains why those six steps keep our work safe.
03Your one-time setup

You do these four things once. After that, you are in the everyday loop above. Daunte will sit with you for about ten minutes to walk through it.

Get added to GitHub Once

Create a free personal account at github.com if you do not have one, then send Daunte your username. He adds you to the BuildwithBPP organization so you can see our files.

Install GitHub Desktop Once

Download the free GitHub Desktop app from desktop.github.com. This is the friendly app with buttons. You will not need a command line. Sign into it with your personal account.

Clone the repo to a normal folder Once

In GitHub Desktop, clone the bpp-workspace project to a plain folder on your computer, such as C:\Users\YourName\Repos. Never put it inside OneDrive or Google Drive. Those services fight with Git and corrupt the files.

Set your name Once

In GitHub Desktop settings, confirm your name and email are yours. This is what stamps every commit as you, so the team always knows who did what. Daunte will check this with you.

04Three rules while you are learning

Never work inside OneDrive

The Git project lives in a plain local folder only. OneDrive and Google Drive corrupt it. Client Word and Excel files still live in OneDrive as always.

Never fix a conflict alone

If Git says two people changed the same thing, stop and ping Daunte. It is not an error, it just needs a human to choose. He will show you.

Always go through a PR

Do not push straight to main. Make a branch, open a Pull Request, let a teammate look. That is the safety net.

Why we are doing this: our skills, notes, and playbooks are the operating system of BPP. Git gives every change an author, a date, and a reason, lets the three of us improve it together without collisions, and makes sure nothing is ever lost. It is the same care we would give a client deliverable, applied to how we run ourselves.
